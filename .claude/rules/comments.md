# コメント規約

## 基本方針

- **What（何をしているか）は原則書かない。** コードを読めば分かることは書かない
- **Why（なぜこの実装・構造なのか）を中心に書く**
- コメントは次の 3 種類を使い分ける：
  - **【意図】** なぜこの実装・構造を選んだのか
  - **【制約】** 前提条件・仕様上そうせざるを得ない理由
  - **【注意】** 将来の変更時・運用時にハマりやすい点

## 形式

- クラス / 関数 / プロパティ → PHPDoc
- 処理のまとまり → ブロックコメント `/* */`
- 行単位のインラインコメント `//` は原則禁止（本当に必要なときのみ）

## 例

```php
/**
 * トップ表示とカテゴリ所属は独立した役割のため、別レコードとして登録する。
 *
 * 【意図】1 行に両方の役割を持たせると、複数カテゴリ同時登録時に
 *         トップ表示が重複する不具合が出るため、役割ごとにレコードを分ける
 * 【注意】カテゴリ削除時にトップ表示レコードまで巻き込んで消さないこと
 */
```
